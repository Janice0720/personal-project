## 3. 核心概念：標準報表架構總覽

### 3.1 報表導覽列的結構

打開 GA4，左側導覽列的「報表」區塊就是標準報表的入口。整體結構如下：

```
報表（Reports）
├── 報表總覽（Reports Snapshot）      ← 儀表板式的摘要
├── 即時（Realtime）                  ← 最近 30 分鐘的即時數據
│
├── 生命週期（Life Cycle）
│   ├── 獲取新客（Acquisition）        ← 使用者從哪裡來？
│   ├── 參與度（Engagement）           ← 使用者在網站做什麼？
│   ├── 營利（Monetization）           ← 使用者帶來多少收益？
│   └── 回訪率（Retention）            ← 使用者是否會再回來？
│
└── 使用者（User）
    ├── 客層（Demographics）           ← 使用者是誰？
    └── 科技（Tech）                   ← 使用者用什麼裝置？
```

用一個日常類比來理解：想像你開了一間電影主題咖啡店（就像 MovieTribe 的實體版），你會想知道：

| 你的疑問 | 對應報表 |
|---------|---------|
| 客人是怎麼知道我們的？走路經過、朋友介紹、還是看到廣告？ | 獲取新客（Acquisition） |
| 客人進店後做了什麼？看了菜單就走、還是坐下來點餐聊天？ | 參與度（Engagement） |
| 客人花了多少錢？哪些商品最賺？ | 營利（Monetization） |
| 客人會再來嗎？多久來一次？ | 回訪率（Retention） |
| 客人是什麼年紀、哪裡人？ | 客層（Demographics） |
| 客人騎車來、開車來、還是搭捷運？ | 科技（Tech） |

### 3.2 標準報表的閱讀框架

每一張標準報表的版面配置大致相同，掌握閱讀框架後就能舉一反三：

```
┌──────────────────────────────────────────────┐
│  ① 日期範圍選擇器（右上角）                      │
│  ② 比較功能按鈕（日期範圍旁）                    │
├──────────────────────────────────────────────┤
│  ③ 摘要指標卡片（Summary Cards）                │
│     顯示 2-4 個關鍵指標的趨勢折線圖              │
├──────────────────────────────────────────────┤
│  ④ 資料表格（Data Table）                       │
│     主要維度 | 指標欄位 1 | 指標欄位 2 | ...     │
│     ─────────────────────────────────         │
│     Organic Search | 1,234 | 00:02:30 | ...   │
│     Direct         |   890 | 00:01:45 | ...   │
│     Social         |   456 | 00:03:10 | ...   │
├──────────────────────────────────────────────┤
│  ⑤ 搜尋列 + 次要維度按鈕 + 篩選器               │
└──────────────────────────────────────────────┘
```

| 元件 | 功能 | 操作提示 |
|------|------|---------|
| 日期範圍 | 決定報表顯示哪段時間的資料 | 建議先設定合理的日期範圍再看數據 |
| 摘要卡片 | 快速掌握趨勢方向 | 點擊不同卡片可切換下方圖表的指標 |
| 資料表格 | 詳細的維度與指標交叉資料 | 點擊欄位標題可排序 |
| 搜尋列 | 在表格中搜尋特定維度值 | 例如搜尋特定頁面路徑 |

## 4. 生命週期報表：獲取新客（Acquisition）

獲取新客報表回答的核心問題是：**「使用者從哪裡來？」**

GA4 提供了兩張獲取報表，名稱很像但視角不同：

| 報表名稱 | 計算對象 | 回答的問題 | 適用場景 |
|---------|---------|-----------|---------|
| 使用者獲取（User Acquisition） | 新使用者的**第一次**造訪 | 新使用者最初從哪個管道發現我們？ | 評估品牌曝光管道的效果 |
| 流量獲取（Traffic Acquisition） | **每一次**工作階段 | 這次造訪是從哪裡來的？ | 評估各管道帶來的整體流量 |

差異類比：想像你第一次在 IG 看到 MovieTribe 的推薦文而造訪網站，之後又透過 Google 搜尋回訪。「使用者獲取」會記住你是「Social（社群）」來的新客；「流量獲取」則會分別記錄一次「Social」和一次「Organic Search（自然搜尋）」。

### 4.1 使用者獲取報表（User Acquisition）

**路徑**：報表 → 生命週期 → 獲取新客 → 使用者獲取

預設主維度是「第一位使用者預設管道分組（First User Default Channel Group）」，代表新使用者第一次到訪的流量管道。

常見管道分組：

| 管道分組（Channel Group） | 含義 | MovieTribe 範例 |
|--------------------------|------|----------------|
| Organic Search | 從 Google、Bing 等搜尋引擎免費點擊進入 | 使用者搜尋「2026 必看電影」找到你的文章 |
| Direct | 直接輸入網址或從書籤進入 | 使用者直接輸入 movietribe.club |
| Social（Organic Social） | 從社群媒體的免費貼文進入 | 從 IG、Facebook 貼文連結點入 |
| Referral | 從其他網站的連結進入 | 其他部落格引用你的電影評論 |
| Paid Search | 從付費搜尋廣告進入 | Google Ads 關鍵字廣告 |
| Paid Social | 從付費社群廣告進入 | Facebook/IG 廣告 |
| Email | 從電子郵件中的連結進入 | 電子報中的文章連結 |
| Unassigned | GA4 無法歸類的流量 | 通常是 UTM 參數設定有誤 |

### 4.2 流量獲取報表（Traffic Acquisition）

**路徑**：報表 → 生命週期 → 獲取新客 → 流量獲取

預設主維度是「工作階段預設管道分組（Session Default Channel Group）」，代表每次工作階段（Session）的流量來源。

報表中的關鍵指標：

| 指標 | 含義 | 怎麼看 |
|------|------|--------|
| 工作階段（Sessions） | 使用者造訪次數 | 流量的「量」 |
| 互動工作階段（Engaged Sessions） | 符合互動條件的造訪（停留 > 10 秒、觸發轉換、或瀏覽 2 頁以上） | 流量的「質」 |
| 參與率（Engagement Rate） | 互動工作階段 / 總工作階段 | 百分比越高代表流量品質越好 |
| 每位使用者互動工作階段數 | 平均每人有幾次有效互動 | 反映使用者的黏著度 |
| 平均參與時間（Avg. Engagement Time） | 使用者實際與頁面互動的平均時間 | 注意：不是停留時間，是「活躍」的時間 |
| 關鍵事件（Key Events） | 轉換次數 | 流量帶來的「成果」 |

### 4.3 MovieTribe 情境：流量從哪來？

> 「我每週在 IG 發 3 篇貼文、偶爾寫 SEO 文章、也有固定讀者直接回訪。想知道哪個管道最有效？」

**操作步驟**：

1. 進入「流量獲取」報表
2. 將日期範圍設定為「最近 28 天」
3. 觀察資料表格，按「工作階段」欄位降序排列

你可能看到類似這樣的結果：

| 管道 | 工作階段 | 參與率 | 平均參與時間 |
|------|---------|--------|------------|
| Organic Search | 820 | 62% | 1 分 45 秒 |
| Direct | 540 | 58% | 1 分 30 秒 |
| Organic Social | 380 | 71% | 2 分 10 秒 |
| Referral | 95 | 55% | 1 分 20 秒 |

**解讀方向**：
- **量**：Organic Search 帶來最多流量 → SEO 文章有效果
- **質**：Organic Social 的參與率最高、平均參與時間最長 → 從社群來的人更投入
- **行動建議**：社群流量雖然不是最多，但品質最好。可以考慮增加社群發文頻率，或在高品質文章中加入社群分享引導

## 5. 生命週期報表：參與度（Engagement）

參與度報表回答的核心問題是：**「使用者在網站上做了什麼？」**

這是 GA4 中最常使用的報表類別，包含三張重要報表。

### 5.1 事件報表（Events）

**路徑**：報表 → 生命週期 → 參與度 → 事件

顯示所有在 GA4 中被記錄的事件，包括自動收集事件、加強型衡量事件，以及你在 Week 5 建立的自訂事件。

| 欄位 | 含義 |
|------|------|
| 事件名稱（Event Name） | 事件的名稱，如 `page_view`、`scroll`、`share` |
| 事件計數（Event Count） | 該事件在所選時間範圍內被觸發的總次數 |
| 使用者總數（Total Users） | 觸發過該事件的不重複使用者數 |

這張報表適合快速檢視：Week 5 設定的自訂事件（例如 `add_to_favorites`、`share`）是否有持續被觸發、數量是否合理。

### 5.2 頁面與畫面報表（Pages and Screens）

**路徑**：報表 → 生命週期 → 參與度 → 頁面與畫面

這是回答「哪些頁面最受歡迎」的核心報表。預設主維度是「頁面標題與畫面類別（Page Title and Screen Class）」。

報表中的關鍵指標：

| 指標 | 含義 | MovieTribe 怎麼看 |
|------|------|-------------------|
| 瀏覽次數（Views） | 頁面被瀏覽的總次數（含重複） | 哪篇電影評論被看最多次 |
| 使用者（Users） | 瀏覽過該頁面的不重複使用者數 | 有多少人看了這篇文章 |
| 每位使用者瀏覽次數（Views per User） | 瀏覽次數 / 使用者數 | 數值高代表使用者會重複看，內容有長期價值 |
| 平均參與時間（Avg. Engagement Time） | 使用者在該頁面的平均活躍時間 | 評估文章是否真的被閱讀 |
| 關鍵事件（Key Events） | 在該頁面觸發轉換的次數 | 哪個頁面最能促進註冊或分享 |

> **小技巧**：點擊主維度的下拉選單，可以切換為「頁面路徑與畫面類別（Page Path and Screen Class）」，用 URL 路徑（如 `/movies/inception`）來辨識頁面，有時候比頁面標題更直觀。

### 5.3 到達網頁報表（Landing Pages）

**路徑**：報表 → 生命週期 → 參與度 → 到達網頁

到達網頁（Landing Page）是使用者進入網站時「第一個看到的頁面」。這張報表回答：**「使用者從哪個頁面開始接觸 MovieTribe？」**

為什麼這很重要？因為到達網頁就是你的「門面」，它的品質決定了訪客會留下來還是馬上離開。

| 指標 | 在到達網頁報表中的意義 |
|------|---------------------|
| 工作階段（Sessions） | 有多少次造訪以這個頁面作為起點 |
| 參與率（Engagement Rate） | 從這個頁面進入的訪客中，有多少人留下來互動 |
| 平均參與時間 | 從這個入口進來的訪客，整體參與時間有多長 |
| 關鍵事件 | 從這個入口進來的訪客，有多少人完成了轉換 |

### 5.4 MovieTribe 情境：哪些頁面最受歡迎？

> 「我想知道哪些電影評論最吸引人，好安排後續的內容方向。」

**操作步驟**：

1. 進入「頁面與畫面」報表
2. 將日期範圍設定為「最近 28 天」
3. 按「瀏覽次數」降序排列，找出 Top 10 頁面

接著交叉比對「到達網頁」報表：

4. 進入「到達網頁」報表
5. 觀察哪些頁面既是熱門頁面，又是主要入口

**解讀方向**：
- 如果某篇電影評論在「頁面與畫面」排名高、在「到達網頁」也排名高 → 這是你的 SEO 明星文章，搜尋引擎直接把人帶到這頁
- 如果某篇文章在「頁面與畫面」排名高、但「到達網頁」排名低 → 使用者是進站後才看到的，可能是站內推薦做得好
- 「到達網頁」的參與率特別低 → 門面出問題了，訪客進來就跑，需要優化頁面內容或載入速度

## 6. 生命週期報表：營利（Monetization）與回訪率（Retention）

### 6.1 營利報表

**路徑**：報表 → 生命週期 → 營利

營利報表用於追蹤電子商務（E-commerce）相關收益。如果網站有販售商品或訂閱服務，這裡會顯示收入、購買次數、每位使用者平均收入等指標。

對 MovieTribe 來說，目前可能尚未啟用電商功能，因此這張報表暫時會是空的。但先了解它的存在即可——未來如果 MovieTribe 推出付費會員、電影周邊商品或付費內容，就會需要用到它。

| 指標 | 含義 |
|------|------|
| 總收益（Total Revenue） | 所有收入的加總 |
| 購買收益（Purchase Revenue） | 來自商品購買的收入 |
| 每位使用者平均收益（Average Revenue per User） | 總收益 / 使用者數 |

### 6.2 回訪率報表

**路徑**：報表 → 生命週期 → 回訪率

回訪率報表回答：**「使用者會不會再回來？」** 對社群網站而言，這是衡量社群黏著度的關鍵指標。

報表中的兩個重要圖表：

| 圖表 | 含義 | MovieTribe 怎麼看 |
|------|------|-------------------|
| 依同類群組劃分的使用者回訪率（User Retention by Cohort） | 新使用者在第 1 天、第 7 天、第 30 天後回訪的比例 | 社群是否能留住人 |
| 依同類群組劃分的使用者參與度（User Engagement by Cohort） | 回訪使用者的平均參與時間趨勢 | 回來的人是否還是很投入 |

**同類群組（Cohort）** 指的是在同一段時間內首次造訪的使用者群組。例如「3 月第一週的新使用者」就是一個同類群組，GA4 會追蹤他們在之後各週的回訪行為。

**MovieTribe 解讀建議**：
- 社群網站的健康回訪率通常在 Day 7 維持 10%-20% 以上
- 如果 Day 1 回訪率極低（< 5%），代表新使用者對第一次體驗不滿意
- 追蹤回訪率的變化趨勢比絕對數字更重要

## 7. 使用者報表：客層與科技

### 7.1 客層報表（Demographics）

**路徑**：報表 → 使用者 → 客層 → 客層總覽

顯示使用者的基本人口統計資訊：

| 維度 | 說明 | 為什麼重要 |
|------|------|-----------|
| 國家/地區（Country） | 使用者所在的國家或地區 | 判斷目標市場是否正確 |
| 城市（City） | 使用者所在城市 | 適合地區性行銷策略 |
| 性別（Gender） | 使用者性別 | 了解受眾組成 |
| 年齡（Age） | 使用者年齡區間 | 了解核心族群 |
| 興趣（Interests） | Google 推斷的使用者興趣類別 | 了解受眾的興趣偏好 |

> **注意**：性別、年齡和興趣資料來自 Google Signals，需要在 GA4 管理介面中啟用，且使用者須登入 Google 帳號並開啟廣告個人化。因此這些資料可能不完整，僅供參考趨勢。

**MovieTribe 應用**：如果發現 80% 的使用者來自台灣、年齡集中在 25-34 歲，就知道核心受眾是台灣的年輕影迷，內容策略可以朝這個方向深耕。

### 7.2 科技報表（Tech）

**路徑**：報表 → 使用者 → 科技 → 科技詳情

顯示使用者使用的裝置與技術環境：

| 維度 | 說明 | 為什麼重要 |
|------|------|-----------|
| 瀏覽器（Browser） | Chrome、Safari、Firefox 等 | 確保網站在主流瀏覽器的相容性 |
| 裝置類別（Device Category） | desktop、mobile、tablet | 判斷行動優先還是桌面優先 |
| 作業系統（Operating System） | Windows、iOS、Android 等 | 了解使用者的設備生態 |
| 螢幕解析度（Screen Resolution） | 使用者的螢幕尺寸 | 影響網頁設計和版面配置 |

**MovieTribe 應用**：如果 70% 的使用者是用手機瀏覽，但網站的手機版體驗不佳（參與率明顯低於桌面版），就知道應該優先改善行動版網頁。

## 8. 進階技巧：次要維度（Secondary Dimension）

### 8.1 什麼是次要維度

標準報表預設只有一個主維度（Primary Dimension）。例如在流量獲取報表中，主維度是「管道分組」。但很多時候，你需要更細緻的視角。

用一個類比來解釋：

你開咖啡店，知道今天來了 100 個客人（主維度 = 日期）。但你還想知道：這 100 個客人中，幾個是 walk-in、幾個是透過外送平台？**「walk-in vs 外送」就是次要維度**——在原本的維度基礎上，再多切一刀。

在 GA4 中，次要維度讓你在一張報表中同時看到兩個維度的交叉結果。

### 8.2 如何加入次要維度

1. 進入任何一張標準報表（例如「流量獲取」）
2. 在資料表格上方，找到藍色的「**+**」按鈕（位於第一個欄位標題旁）
3. 點擊後會出現維度選單，可搜尋或按類別瀏覽
4. 選擇你想加入的次要維度（例如「裝置類別」）
5. 表格會自動展開，顯示主維度 × 次要維度的交叉結果

### 8.3 交叉分析的實務應用

**範例一：流量來源 × 裝置類別**

> 「想知道從社群來的使用者，是用手機還是電腦？」

操作：流量獲取報表 → 加入次要維度「裝置類別（Device Category）」

| 管道 | 裝置 | 工作階段 | 參與率 |
|------|------|---------|--------|
| Organic Social | mobile | 310 | 73% |
| Organic Social | desktop | 70 | 65% |
| Organic Search | desktop | 480 | 64% |
| Organic Search | mobile | 340 | 59% |

**洞察**：社群流量以手機為主（310 vs 70），且手機的參與率更高。合理——使用者在手機上滑 IG 時點擊連結進入。搜尋流量則桌面與手機較為均衡。

**範例二：到達網頁 × 來源/媒介**

> 「想知道熱門到達網頁的流量分別是從哪裡來的。」

操作：到達網頁報表 → 加入次要維度「工作階段來源/媒介（Session Source / Medium）」

這可以告訴你：某篇文章是靠 SEO 帶來流量、還是靠社群分享。

**範例三：頁面標題 × 自訂維度（電影類型）**

> 「想看各電影類型的文章表現差異。」

操作：頁面與畫面報表 → 加入次要維度「電影類型」（Week 6 註冊的自訂維度）

這樣就能看出：科幻類文章跟動作類文章，哪種的瀏覽量和參與時間更好。

## 9. 進階技巧：比較功能（Comparisons）

### 9.1 什麼是比較功能

如果說次要維度是「在一張表裡多看一個維度」，比較功能則是「同時看兩群人的表現差異」。

比較功能會在報表上方的折線圖和摘要卡片中，用不同顏色疊加顯示兩組（或多組）資料，讓你一眼看出差異。

### 9.2 如何建立比較條件

1. 在報表頁面的右上方，點擊「**新增比較項目**」（Add Comparison）
2. 選擇比較的維度（例如「裝置類別」）
3. 選擇維度值（例如「mobile」）
4. 點擊「**套用**」
5. 報表會同時顯示「所有使用者」和「mobile 使用者」的資料
6. 可繼續新增更多比較條件（最多 4 組）

### 9.3 常見比較情境

**情境一：行動裝置 vs 桌面**

| 比較條件 | 設定 |
|---------|------|
| 比較 A | 裝置類別 = mobile |
| 比較 B | 裝置類別 = desktop |

**觀察重點**：兩種裝置的參與率、平均參與時間、轉換率是否有顯著差異？如果手機的參與率明顯低於桌面，可能代表手機版的使用體驗有待優化。

**情境二：新訪客 vs 回訪客**

| 比較條件 | 設定 |
|---------|------|
| 比較 A | 新/回訪 = New visitor |
| 比較 B | 新/回訪 = Returning visitor |

**觀察重點**：回訪客的參與時間通常較長，但新訪客的數量反映成長力道。如果回訪客的比例持續下降，代表社群黏著度出了問題。

**情境三：特定國家/地區**

| 比較條件 | 設定 |
|---------|------|
| 比較 A | 國家/地區 = Taiwan |
| 比較 B | 國家/地區 = Hong Kong |

**觀察重點**：不同地區的使用者行為差異，幫助判斷是否值得投入跨地區經營。

> **次要維度 vs 比較功能的差別**：次要維度是在表格裡「展開更多欄位」，適合做細粒度的數據查找；比較功能是在圖表上「疊加兩條線」，適合做視覺化的群組對比。兩者可以搭配使用。

## 10. 實作練習

### 練習一：找出 MovieTribe 的前三大流量來源（10 分鐘）

1. 開啟 GA4 → 報表 → 獲取新客 → 流量獲取
2. 日期範圍設定為「最近 28 天」
3. 按「工作階段」降序排列
4. 記錄前三大管道的名稱、工作階段數、參與率
5. 寫下你的觀察：哪個管道量最大？哪個管道品質最好？

### 練習二：找出最受歡迎的 Top 5 頁面（10 分鐘）

1. 開啟 GA4 → 報表 → 參與度 → 頁面與畫面
2. 日期範圍設定為「最近 28 天」
3. 按「瀏覽次數」降序排列
4. 記錄前五名頁面的標題、瀏覽次數、平均參與時間
5. 思考：排名第一的是首頁嗎？如果是特定文章頁，這代表什麼？

### 練習三：用次要維度做一次交叉分析（10 分鐘）

1. 沿用練習一的流量獲取報表
2. 點擊「+」按鈕，加入次要維度「裝置類別」
3. 觀察各管道在不同裝置上的表現差異
4. 寫下至少一個發現，例如：「社群流量有 __% 來自手機」

### 練習四：用比較功能對比兩組使用者（10 分鐘）

1. 在任一報表右上方，點擊「新增比較項目」
2. 建立比較：裝置類別 = mobile vs 裝置類別 = desktop
3. 觀察摘要卡片和折線圖的差異
4. 完成後移除比較條件（點擊比較條件旁的「×」）

## 12. FAQ — 常見問題

**Q1：標準報表和探索報表（Explorations）有什麼不同？**

標準報表是 GA4 預先建好的固定格式報表，點開就能看，適合回答常見的基礎問題。探索報表（我們會在 Week 8-9 深入學習）是完全自訂的分析畫布，你可以自由拖放維度和指標、建立漏斗和路徑分析。簡單說：標準報表是「預設套餐」，探索報表是「自助吧台」。

**Q2：我的報表裡很多數據顯示「(not set)」，這是什麼意思？**

「(not set)」代表 GA4 沒有收到該維度的值。常見原因包括：使用者的瀏覽器阻擋了追蹤、隱私設定限制了資料收集、或是 UTM 參數漏設。少量的 (not set) 是正常的，如果佔比超過 20%，就需要排查追蹤設定是否有問題。

**Q3：參與率和跳出率（Bounce Rate）有什麼關係？**

在 GA4 中，參與率（Engagement Rate）基本上是跳出率的相反。跳出率 = 1 - 參與率。GA4 預設顯示參與率而非跳出率，因為 GA4 認為正面指標更直覺。如果你需要跳出率，可以在報表中透過「自訂報表」功能手動加入跳出率欄位。

**Q4：「使用者獲取」和「流量獲取」我應該看哪一張？**

看你想回答什麼問題。想知道「新客從哪來」→ 使用者獲取；想知道「每次造訪從哪來」→ 流量獲取。日常使用中，「流量獲取」通常更常被使用，因為它反映的是所有流量的全貌。

**Q5：次要維度可以加超過一個嗎？**

標準報表中只能加一個次要維度。如果你需要同時用三個以上的維度做交叉分析，就需要使用探索報表（Week 8 會教）。

**Q6：為什麼我在報表中看不到 Week 5 設定的自訂事件？**

確認以下幾點：(1) 事件是否已在正式環境中成功觸發（不只是 GTM 預覽模式）；(2) 是否已等待超過 24-48 小時；(3) 日期範圍是否涵蓋事件觸發的時間。在事件報表的搜尋列中直接輸入事件名稱確認。

**Q7：報表中的「Unassigned」管道代表什麼？**

Unassigned 代表 GA4 無法將該流量歸入任何預設管道分組。最常見原因是 UTM 參數格式不正確。例如 `utm_medium` 寫成了不符合 GA4 管道規則的值。檢查你的社群連結是否有正確設定 UTM 參數。
