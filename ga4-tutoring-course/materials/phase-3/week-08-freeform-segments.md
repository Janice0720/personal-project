## 3. 核心概念：為什麼需要探索報表？

### 3.1 標準報表的限制

在 Week 7 中，我們已學會閱讀 GA4 的標準報表（Standard Reports）。標準報表就像餐廳的「套餐」——菜色固定、上菜順序固定，適合日常快速瀏覽，但遇到特殊分析需求就會碰壁。

| 限制 | 說明 | 實際影響 |
|------|------|---------|
| 維度組合固定 | 無法同時交叉比較三個以上維度 | 想看「裝置 × 來源 × 頁面」的交叉分析做不到 |
| 篩選彈性不足 | 只能用簡單的篩選器 | 想篩選「停留超過 60 秒且來自 Facebook」的使用者困難 |
| 視覺化選項有限 | 多半只有表格或簡單趨勢圖 | 無法自由切換成散佈圖、長條圖等 |
| 無法建立區隔比較 | 不支援自訂區隔 | 想對比「新訪客 vs 回訪客」的行為差異需另找方法 |

**一句話總結**：標準報表回答「發生了什麼」，探索報表回答「為什麼會這樣」。

### 3.2 探索報表的類型總覽

GA4 的探索報表提供多種分析技巧（Techniques），本週先聚焦最常用的「自由形式」，後續兩週再學其他類型。

| 探索類型 | 英文名稱 | 功能簡述 | 學習週次 |
|----------|---------|---------|:--------:|
| **自由形式** | Free-form | 自由組合維度、指標與視覺化，類似 Excel 樞紐分析表 | **本週** |
| 漏斗探索 | Funnel Exploration | 分析使用者經過多步驟的轉換率與流失率 | Week 9 |
| 路徑探索 | Path Exploration | 視覺化使用者在頁面間的瀏覽路徑 | Week 9 |
| 區隔重疊 | Segment Overlap | 觀察不同使用者區隔的重疊情況 | 延伸 |
| 同類群組探索 | Cohort Exploration | 依共同特徵分群，追蹤長期行為趨勢 | 延伸 |
| 使用者生命週期 | User Lifetime | 分析使用者從首次造訪到最近活動的完整歷程 | 延伸 |

## 4. 自由形式探索（Free-form Exploration）

### 4.1 介面三欄結構

進入探索報表後，你會看到分成三大區塊的操作介面。把它想像成一個料理台：

```
┌──────────────┬──────────────────┬─────────────────────────┐
│   變數欄      │   標籤設定欄      │       畫布               │
│  (Variables)  │  (Tab Settings)  │     (Canvas)             │
│              │                  │                          │
│  ◆ 日期範圍   │  ◆ 視覺化類型    │                          │
│  ◆ 區隔       │  ◆ 列（Rows）    │    報表在這裡即時呈現     │
│  ◆ 維度       │  ◆ 欄（Columns） │                          │
│  ◆ 指標       │  ◆ 值（Values）  │                          │
│              │  ◆ 篩選器        │                          │
│              │                  │                          │
│  食材倉庫     │  料理配方         │    成品擺盤              │
│  (放什麼可用)  │  (怎麼組合)      │    (最終呈現)             │
└──────────────┴──────────────────┴─────────────────────────┘
```

| 區塊 | 類比 | 功能 |
|------|------|------|
| 變數欄（Variables） | 食材倉庫 | 選擇這張報表可用的「食材」：匯入哪些維度、指標、區隔 |
| 標籤設定欄（Tab Settings） | 料理配方 | 決定如何組合食材：把維度拖到「列」，指標拖到「值」 |
| 畫布（Canvas） | 成品擺盤 | 即時顯示報表結果，可直接在畫布上互動 |

### 4.2 操作方式：拖拉式組合報表

自由形式的操作核心就是「拖拉」——把左邊的維度和指標拖到中間的對應欄位，右邊畫布自動更新。如果你用過 Excel 的樞紐分析表（Pivot Table），概念幾乎一樣：

| Excel 樞紐分析表 | GA4 自由形式 | 作用 |
|------------------|-------------|------|
| 列（Row Labels） | 列（Rows） | 報表左側的分類依據，例如「國家」、「裝置」 |
| 欄（Column Labels） | 欄（Columns） | 報表上方的次分類，例如「月份」 |
| 值（Values） | 值（Values） | 報表中的數字，例如「工作階段數」 |
| 篩選（Report Filter） | 篩選器（Filters） | 縮小資料範圍，例如只看「來自台灣」 |

### 4.3 視覺化選項

| 視覺化類型 | 適合場景 | MovieTribe 範例 |
|-----------|---------|----------------|
| 表格（Table） | 精確數字、多維度交叉分析 | 各頁面的工作階段數、互動時間 |
| 甜甜圈圖（Donut Chart） | 顯示組成比例 | 各裝置類別的使用者佔比 |
| 折線圖（Line Chart） | 趨勢隨時間的變化 | 每日活躍使用者數 |
| 散佈圖（Scatter Plot） | 兩個指標的關聯性 | 停留時間 vs 轉換率 |
| 長條圖（Bar Chart） | 比較不同類別的大小 | 各流量來源的工作階段數 |
| 地理地圖（Geo Map） | 地理分布分析 | 使用者所在國家/城市 |

> 先用表格確認數據正確，再切換成圖表呈現給他人看。表格是「分析用」，圖表是「溝通用」。

## 5. 實作步驟 A：建立第一張自由形式報表

以「分析 MovieTribe 各頁面的流量與互動表現」為目標，從頭建立一張探索報表。

### 5.1 建立新的探索報表

1. 登入 [GA4 後台](https://analytics.google.com/)，確認選擇的是 MovieTribe 的 GA4 資源
2. 左側選單點擊「**探索**」（Explore）
3. 點擊「**空白**」（Blank）建立全新的探索報表
4. 在左上角將報表命名為 `MovieTribe 頁面流量分析`
5. 設定日期範圍：點擊變數欄中的日期範圍，選擇「**最近 28 天**」

### 5.2 匯入維度與指標

**匯入維度**——在變數欄的「維度」區塊旁點擊「**+**」號，搜尋並勾選：

| 維度名稱 | 英文名稱 | 用途 |
|----------|---------|------|
| 頁面標題 | Page title | 辨識頁面內容 |
| 裝置類別 | Device category | 區分行動 / 電腦 / 平板 |
| 工作階段預設管道群組 | Session default channel group | 流量來源管道 |

**匯入指標**——同樣點擊「**+**」號，搜尋並勾選：

| 指標名稱 | 英文名稱 | 用途 |
|----------|---------|------|
| 工作階段 | Sessions | 造訪次數 |
| 活躍使用者 | Active users | 不重複使用者數 |
| 平均互動時間 | Average engagement time | 使用者平均停留時間 |
| 事件計數 | Event count | 事件觸發總次數 |

### 5.3 組合報表並調整

1. **視覺化類型**：先保持「表格」
2. **列（Rows）**：把「**頁面標題**」拖到標籤設定欄的「列」區塊
3. **值（Values）**：依序把「工作階段」、「活躍使用者」、「平均互動時間」拖到「值」區塊
4. 畫布會自動出現一張表格：

```
┌──────────────────────────────┬──────────┬──────────┬──────────┐
│        頁面標題               │ 工作階段  │ 活躍使用者│ 平均互動  │
│                              │          │          │ 時間     │
├──────────────────────────────┼──────────┼──────────┼──────────┤
│ MovieTribe - 首頁             │   1,250  │    980   │  1:35    │
│ 全面啟動 - MovieTribe         │    320   │    280   │  3:22    │
│ 沙丘 - MovieTribe            │    285   │    240   │  2:58    │
│ ...                          │   ...    │   ...    │  ...     │
└──────────────────────────────┴──────────┴──────────┴──────────┘
```

**進階調整：**

- **排序**：點擊欄位標題切換升降序，找出最熱門頁面
- **顯示列數**：預設 10 列，可調整為 25 或 50
- **新增次維度**：把「裝置類別」拖到「欄」（Columns），表格變成交叉分析格式
- **篩選器**：設定「裝置類別 完全符合 mobile」，只看行動裝置數據

## 6. 核心概念：使用者區隔（Segments）

### 6.1 區隔的三種類型

**區隔（Segments）** 是探索報表中最強大的分析工具之一——把全部使用者「切成不同群組」，比較群組間的行為差異。

想像你經營一家實體電影院。每天有各種觀眾走進來——情侶、家庭、影評人。你想知道「情侶觀眾比較喜歡看哪類電影？」就需要先把觀眾分群。區隔做的就是這件事。

| 區隔類型 | 英文名稱 | 分群依據 | 類比 | 範例 |
|----------|---------|---------|------|------|
| 使用者區隔 | User Segment | 使用者本身的特徵 | 以「會員卡」來分——只要這個人曾符合條件，所有行為都被納入 | 「曾購買的使用者」 |
| 工作階段區隔 | Session Segment | 單次造訪的行為 | 以「這次來」的情況分——只看這次造訪有無符合條件 | 「本次有觸發轉換的工作階段」 |
| 事件區隔 | Event Segment | 單一事件的條件 | 以「單一動作」分——只看特定事件 | 「瀏覽首頁的事件」 |

**簡單記法**：使用者區隔看「人」、工作階段區隔看「這次造訪」、事件區隔看「那個動作」。

### 6.2 條件設定邏輯

建立區隔的核心是設定條件——用什麼規則把使用者分群。條件之間可用 **AND（且）** 表示所有條件都要符合，或 **OR（或）** 表示至少一個符合。

### 6.3 常見區隔範例

| 區隔名稱 | 區隔類型 | 條件設定 | 分析用途 |
|----------|---------|---------|---------|
| 行動版使用者 | 使用者區隔 | 裝置類別 完全符合 `mobile` | 手機使用者的瀏覽行為 |
| 電腦版使用者 | 使用者區隔 | 裝置類別 完全符合 `desktop` | 對比電腦使用者的行為 |
| 新訪客 | 使用者區隔 | 新使用者/既有使用者 完全符合 `new` | 首次造訪者的行為模式 |
| 回訪客 | 使用者區隔 | 新使用者/既有使用者 完全符合 `returning` | 回訪者的忠誠度指標 |
| 社群來源流量 | 工作階段區隔 | 管道群組 完全符合 `Organic Social` | 社群行銷的導流效果 |
| 高互動工作階段 | 工作階段區隔 | 互動時間 > 60 秒 | 真正對內容有興趣的造訪 |

## 7. 實作步驟 B：建立區隔並套用到報表

延續第 5 節的報表，加入區隔比較「行動版使用者」與「電腦版使用者」的行為差異。

**建立「行動版使用者」區隔：**

1. 在變數欄的「**區隔**」旁點擊「**+**」號
2. 選擇「**使用者區隔**」（User Segment）
3. 命名為 `行動版使用者`
4. 點擊「**新增條件**」→ 維度選「**裝置類別**」→ 運算符「**完全符合**」→ 值輸入 `mobile`
5. 點擊「**儲存並套用**」

**建立「電腦版使用者」區隔：**

以同樣步驟建立，條件值改為 `desktop`。

**套用比較：**

1. 將兩個區隔都拖到標籤設定欄的「**區隔比較**」區塊（最多可同時比較 4 個）
2. 畫布自動更新，每個指標分成兩組顯示：

```
┌──────────────────┬──────────────────────┬──────────────────────┐
│                  │    行動版使用者        │    電腦版使用者        │
│    頁面標題       ├───────┬───────┬──────┼───────┬───────┬──────┤
│                  │工作階段│活躍   │平均互│工作階段│活躍   │平均互│
│                  │       │使用者 │動時間│       │使用者 │動時間│
├──────────────────┼───────┼───────┼──────┼───────┼───────┼──────┤
│ MovieTribe - 首頁│  780  │  650  │ 1:10 │  420  │  300  │ 2:15 │
│ 全面啟動         │  180  │  160  │ 2:45 │  130  │  110  │ 4:30 │
└──────────────────┴───────┴───────┴──────┴───────┴───────┴──────┘
```

**觀察重點**：行動版流量是否佔大宗？電腦版互動時間是否較長？哪些頁面在行動版表現特別好或差？

> 同一組數據加上不同的「切面」，就能看到完全不同的故事。就像把白光通過三稜鏡，才能看到彩虹的各種顏色。

## 8. 異常偵測（Anomaly Detection）

### 8.1 什麼是異常偵測？

**異常偵測（Anomaly Detection）** 利用機器學習（Machine Learning）自動識別數據中的離群值（Outlier）。

想像 MovieTribe 平時每天大約 200 個工作階段，突然某天變成 2,000——是好事（影評爆紅）還是壞事（追蹤代碼 Bug）？異常偵測會自動標記這種「明顯偏離常態」的數據點。

GA4 使用貝氏狀態空間模型（Bayesian State Space Model）根據歷史趨勢計算每天的預期值與合理上下限——你不需要理解數學，只要知道它會自動建立「正常範圍」，超出範圍的就會被標記。

### 8.2 啟用與解讀

**啟用步驟：**

1. 在自由形式報表中，將視覺化類型切換為「**折線圖**」
2. 找到「**異常偵測**」開關，切換為「**開**」
3. 折線圖上會出現：藍色實線（實際數據）、淺藍色陰影（正常範圍）、圓點標記（異常點）

**解讀三步驟：**

| 步驟 | 動作 | 目的 |
|------|------|------|
| 識別 | 點擊異常點，查看實際值與預期值 | 確認偏離程度 |
| 歸因 | 比對日期，回想是否有特殊事件 | 找出原因 |
| 行動 | 根據原因判斷後續動作 | 複製成功模式或修復問題 |

**常見異常情境：**

| 異常類型 | 可能原因 | 建議行動 |
|----------|---------|---------|
| 流量飆升 | 影評被網紅分享、貼文爆紅 | 記錄成功因素，複製到其他內容 |
| 流量驟降 | 網站故障、頁面 404、追蹤代碼壞掉 | 立即排查技術問題 |
| 互動時間異常高 | 發布深度長文、或網站載入過慢 | 區分正面信號還是效能問題 |
| 轉換率下降 | 註冊流程壞掉、按鈕樣式跑掉 | 檢查轉換路徑是否正常 |

> 異常偵測只告訴你「這裡有異常」，原因需要你結合業務脈絡判斷——這也是最需要人的經驗與直覺的環節。

## 9. MovieTribe 應用情境

### 情境一：不同裝置的使用者行為比較

> 「手機使用者和電腦使用者的瀏覽行為有什麼差異？」

| 設定項目 | 設定內容 |
|----------|---------|
| 區隔 | 行動版使用者 / 電腦版使用者 |
| 列 | 頁面標題 |
| 值 | 工作階段、平均互動時間、每位使用者互動工作階段數 |

**可能洞察**：手機使用者多集中在首頁與電影清單頁，互動時間較短；電腦使用者較常看長篇影評，停留較久。若手機流量佔比超過 70%，應優先投資行動版體驗。

### 情境二：各來源管道的參與度分析

> 「從 Facebook、Google 搜尋、直接造訪來的使用者，誰的參與度最高？」

| 設定項目 | 設定內容 |
|----------|---------|
| 列 | 工作階段預設管道群組 |
| 值 | 工作階段、活躍使用者、平均互動時間 |
| 排序 | 按平均互動時間降序 |

**可能洞察**：自然搜尋來的使用者互動最深（帶著目的而來），社群流量多但停留短（逛逛就走），直接流量回訪率高（忠實讀者）。

### 情境三：熱門電影頁面分析

> 「哪些電影頁面最受歡迎？」

| 設定項目 | 設定內容 |
|----------|---------|
| 列 | 頁面標題 |
| 值 | 工作階段、事件計數、平均互動時間 |
| 篩選器 | 頁面路徑 包含 `/movies/` |

**進階玩法**：同時套用「社群來源」和「搜尋來源」兩個區隔，比較社群上受歡迎的電影 vs 大眾主動搜尋的電影——前者加強社群推廣，後者加強 SEO 優化。

## 11. FAQ — 常見問題

**Q1：探索報表和標準報表有什麼差別？什麼時候該用哪個？**

標準報表是預設固定格式，適合日常快速瀏覽關鍵指標。探索報表是你自己設計的報表，適合深入分析、交叉比較、區隔對比。日常監控用標準報表，深入分析用探索報表。

**Q2：探索報表最多可以放幾個維度和指標？**

每張可匯入 20 個維度和 20 個指標。列最多 5 個維度、欄最多 5 個維度、值最多 10 個指標。建議一開始 2-3 個維度搭配 3-4 個指標就足夠。

**Q3：區隔可以在不同探索報表中重複使用嗎？**

每張報表的區隔是獨立的，不會自動同步到其他報表。建議在筆記中記錄常用區隔的條件，方便快速重建。

**Q4：區隔和篩選器有什麼差別？**

篩選器（Filters）直接過濾資料，只看符合條件的數據。區隔（Segments）把資料分組，讓你同時看到不同群組做比較。只需要縮小範圍用篩選器，需要對比兩群人用區隔。

**Q5：異常偵測會不會誤判？**

會。資料量越大、模式越穩定，偵測越準確。小型網站流量波動本就較大，異常偵測的參考價值有限。把它當「提醒機制」而非「絕對判斷」。

**Q6：探索報表顯示「資料不足」怎麼辦？**

依序排查：(1) 日期範圍是否正確；(2) 篩選器條件是否過嚴——先移除所有篩選器試試；(3) GA4 是否有持續接收資料——到即時報表確認。
