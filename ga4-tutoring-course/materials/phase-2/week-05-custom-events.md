## 3. 核心概念：自訂事件的策略思考

### 3.1 什麼時候需要自訂事件？

GA4 的事件體系共有四個層級，在 Week 4 我們已學過前三類。快速回顧：

| 事件類型 | 誰負責建立 | 範例 |
|----------|-----------|------|
| 自動收集事件（Automatically Collected） | GA4 自動收集 | `first_visit`、`session_start` |
| 加強型衡量事件（Enhanced Measurement） | GA4 開關式啟用 | `scroll`、`click`（外連結點擊） |
| 建議事件（Recommended Events） | 手動建立，但名稱由 Google 建議 | `sign_up`、`share`、`search` |
| **自訂事件（Custom Events）** | **完全由你定義名稱與參數** | `view_movie_detail`、`click_recommendation` |

**決策邏輯：**

```
你想追蹤的行為
      │
      ▼
GA4 自動收集了嗎？
     ╱       ╲
    是        否
    │         │
    ▼         ▼
 不需額外    加強型衡量
 設定       有涵蓋嗎？
             ╱       ╲
            是        否
            │         │
            ▼         ▼
         確認開關    Google 建議
         已打開     事件清單中
                    有對應的嗎？
                     ╱       ╲
                    是        否
                    │         │
                    ▼         ▼
                使用建議    建立自訂
                事件名稱    事件
```

用一句話總結：**能用現成的就用現成的，真的沒有才自訂。**

這就像點菜——餐廳菜單上有的菜就直接點，只有菜單上找不到的特殊料理，才需要跟廚師「客製化」。自訂事件就是你和 GA4 之間的客製化訂單。

### 3.2 事件命名規範

GA4 對事件名稱有明確的規則限制。違反規則的事件名稱將**不會被 GA4 接受**，資料就會遺失，所以務必遵守。

**硬性規則（違反則事件無效）：**

| 規則 | 說明 | 正確範例 | 錯誤範例 |
|------|------|---------|---------|
| 開頭必須是英文字母 | 不能以數字或符號開頭 | `click_share` | `1st_click` |
| 只能包含英文字母、數字和底線 | 不接受空格、連字號、中文 | `view_movie_detail` | `view-movie-detail` |
| 名稱區分大小寫 | `Add_Cart` 和 `add_cart` 會被視為兩個不同事件 | 統一使用小寫 | 混用大小寫 |
| 長度限制 40 個半形字元 | 超過 40 字元的部分會被截斷 | `click_recommendation` (20 字元) | 過長的名稱 |
| 不得使用保留前綴 | `_`（底線開頭）和 `firebase_`、`google_`、`ga_` 為系統保留 | `custom_signup` | `_signup`、`google_click` |

**軟性規範（建議遵守的最佳實踐）：**

- **統一使用 snake_case**：全小寫加底線分隔，例如 `view_movie_detail`
- **使用「動作_對象」結構**：先描述動作，再描述對象，例如 `click_share_button`、`submit_registration_form`
- **保持命名一致性**：同一網站的所有事件遵循同一套命名邏輯

**MovieTribe 事件命名範例：**

| 追蹤需求 | 事件名稱 | 命名邏輯 |
|----------|---------|---------|
| 使用者點擊電影推薦按鈕 | `click_recommendation` | 動作（click）+ 對象（recommendation） |
| 使用者提交會員註冊表 | `submit_registration` | 動作（submit）+ 對象（registration） |
| 使用者分享內容到社群 | `share_to_social` | 動作（share）+ 對象（to_social） |
| 使用者觀看電影詳細資訊 | `view_movie_detail` | 動作（view）+ 對象（movie_detail） |

### 3.3 參數設計的最佳實踐

事件名稱告訴你「發生了什麼事」，**事件參數（Event Parameters）** 則告訴你「細節是什麼」。

用寄包裹來比喻：事件名稱就像包裹外箱上寫的「這是什麼」（例如「禮物」），參數就是裝在裡面的明細清單（收件人、品項、金額、寄件日期⋯⋯）。

**參數的硬性限制：**

| 限制項目 | 規格 |
|----------|------|
| 每個事件最多的參數數量 | 25 個 |
| 參數名稱長度 | 最多 40 個半形字元 |
| 參數值長度（文字型） | 最多 100 個半形字元 |
| 參數名稱規則 | 與事件名稱相同（英文字母開頭、只能包含英文字母、數字、底線） |

**參數設計原則：**

1. **只傳遞有分析價值的資訊**：不要為了「萬一用到」而塞滿 25 個參數，先想清楚「這個參數拿到報表裡能怎麼用」
2. **使用一致的命名風格**：與事件名稱一樣使用 snake_case
3. **區分維度型與指標型參數**：
   - 維度型（文字）：用來分類，例如 `button_location`、`movie_genre`
   - 指標型（數字）：用來計算，例如 `click_count`、`scroll_percentage`

**MovieTribe 參數設計範例：**

以 `click_recommendation` 事件為例：

| 參數名稱 | 類型 | 說明 | 範例值 |
|----------|------|------|--------|
| `click_text` | 文字 | 被點擊按鈕的文字 | `觀看推薦` |
| `button_id` | 文字 | 按鈕的 HTML ID | `rec-btn-01` |
| `page_location` | 文字 | 點擊發生的頁面路徑 | `/movies/inception` |
| `movie_title` | 文字 | 相關的電影名稱 | `全面啟動` |

## 4. 實作步驟：在 GTM 中建立自訂事件

### 4.1 整體流程總覽

在 GTM 中建立一個完整的自訂事件，需要經過以下三個步驟：

```
步驟一：建立觸發條件        步驟二：建立 GA4 事件代碼       步驟三：預覽與除錯
──────────────           ──────────────────          ──────────────
定義「什麼行為」       →    定義「送什麼事件」       →    驗證「是否正確」
要觸發這個事件               以及「帶哪些參數」            然後發布上線
```

以下以「追蹤 MovieTribe 電影推薦按鈕點擊」為範例，完整走過一次流程。

### 4.2 新增 GA4 事件代碼

**操作步驟：**

1. 登入 [GTM 後台](https://tagmanager.google.com/)，進入 MovieTribe 的 GTM 容器
2. 左側選單點擊「**代碼**」→ 點擊「**新增**」
3. 將代碼命名為 `GA4 Event - click_recommendation`

   > 命名建議採用「代碼類型 - 事件名稱」的格式，容器內代碼一多時容易辨識。

4. 點擊「**代碼設定**」區塊 → 選擇代碼類型「**Google Analytics：GA4 事件**」
5. 在「設定代碼」下拉選單中，選擇你在 Week 3 建立的 `Google Tag - GA4`

   > 這裡的邏輯是：GA4 事件代碼必須「搭載」在 Google 代碼已建立的連線上。就像你要寄包裹，得先確認物流公司（Google 代碼）已經開通服務。

6. 在「**事件名稱**」欄位輸入：`click_recommendation`
7. 展開「**事件參數**」區塊，點擊「**新增列**」來設定參數：

   | 參數名稱 | 值 |
   |----------|-----|
   | `click_text` | `{{Click Text}}` |
   | `button_id` | `{{Click ID}}` |
   | `page_location` | `{{Page Path}}` |

   > `{{Click Text}}`、`{{Click ID}}`、`{{Page Path}}` 是 GTM 內建變數的引用語法。GTM 會在事件觸發時，自動把這些變數替換成實際的值。

8. 先不設觸發條件（下一步設定），點擊右上角「**儲存**」

### 4.3 設定觸發條件

代碼知道要「做什麼」了，現在要告訴它「什麼時候做」——也就是設定觸發條件。

**情境 A：追蹤按鈕點擊**

1. 左側選單點擊「**觸發條件**」→ 點擊「**新增**」
2. 將觸發條件命名為 `Click - Recommendation Button`
3. 點擊「**觸發條件設定**」區塊 → 選擇「**點擊 - 所有元素**」

   > 「所有元素」和「僅連結」的差別：
   > - **僅連結（Just Links）**：只追蹤 `<a>` 標籤的點擊
   > - **所有元素（All Elements）**：追蹤所有 HTML 元素的點擊（包括 `<button>`、`<div>`、`<span>` 等）
   >
   > 因為按鈕通常是 `<button>` 而非 `<a>` 標籤，所以選擇「所有元素」。

4. 選擇「**部分點擊**」（Some Clicks），設定篩選條件：

   | 條件欄位 | 運算符 | 值 |
   |----------|--------|-----|
   | Click Text | 包含 | 觀看推薦 |

   > 也可以使用 Click ID 或 Click Classes 來篩選，取決於網站的 HTML 結構。使用 Click Text 的好處是直觀易懂，但如果按鈕文字可能改變，用 Click ID 或 Click Classes 會更穩定。

5. 點擊「**儲存**」

**情境 B：追蹤表單提交**

1. 新增觸發條件，命名為 `Form - Registration Submit`
2. 選擇「**表單送出**」觸發類型
3. 勾選「**等待代碼**」（Wait for Tags），設定最長等待時間 2000 毫秒

   > 「等待代碼」的作用：確保 GA4 事件代碼有足夠時間發送資料，才讓瀏覽器繼續處理表單跳轉。否則頁面可能在事件發送完成前就跳走了，導致資料遺失。

4. 選擇「**部分表單**」（Some Forms），設定篩選條件：

   | 條件欄位 | 運算符 | 值 |
   |----------|--------|-----|
   | Form ID | 等於 | registration-form |

5. 點擊「**儲存**」

**將觸發條件綁定到代碼：**

1. 回到「**代碼**」頁面，找到剛才建立的 `GA4 Event - click_recommendation`
2. 點擊進入編輯 → 在「**觸發條件**」區塊點擊
3. 選擇剛才建立的 `Click - Recommendation Button`
4. 點擊「**儲存**」

### 4.4 配置變數以傳遞參數

在 4.2 步驟中，我們已經使用了 `{{Click Text}}`、`{{Click ID}}`、`{{Page Path}}` 等內建變數。但如果你需要傳遞的資訊不在內建變數的範圍內，就需要建立**使用者定義變數（User-Defined Variables）**。

**範例：建立一個取得電影標題的自訂 JavaScript 變數**

假設 MovieTribe 的電影頁面有一個 `<h1>` 標籤顯示電影名稱，我們可以用自訂 JavaScript 取得它：

1. 左側選單點擊「**變數**」→ 在「使用者定義變數」區塊點擊「**新增**」
2. 命名為 `JS - Movie Title`
3. 變數類型選擇「**自訂 JavaScript**」
4. 輸入以下程式碼：

```javascript
function() {
  var titleElement = document.querySelector('h1');
  return titleElement ? titleElement.innerText : 'unknown';
}
```

5. 點擊「**儲存**」

完成後，就可以在代碼的事件參數中使用 `{{JS - Movie Title}}` 來傳遞電影名稱。

> 建立自訂 JavaScript 變數時，不需要你自己會寫程式。上課時老師會提供程式碼，你只需要了解這段程式碼的功能——從頁面的 `<h1>` 標籤取得電影名稱。未來遇到類似需求，可以請工程師協助撰寫。

**變數命名建議：**

| 變數類型 | 命名格式 | 範例 |
|----------|---------|------|
| 內建變數 | GTM 預設名稱 | Click Text、Page Path |
| 常數 | `Const - 用途` | `Const - GA4 Measurement ID` |
| 資料層變數 | `DLV - 欄位名稱` | `DLV - movie_genre` |
| 自訂 JavaScript | `JS - 用途` | `JS - Movie Title` |

## 5. Debug 除錯技巧：預覽模式與 DebugView

建立完代碼、觸發條件和變數之後，**千萬不要直接發布**。務必先用除錯工具確認一切正確。

這就像寄出重要文件前，你會先印出來仔細校對一遍——除錯就是代碼發布前的「校對」步驟。

### 5.1 GTM 預覽模式除錯

GTM 預覽模式（Preview Mode）讓你在不影響正式網站的情況下，測試代碼是否按照預期觸發。

**進入預覽模式：**

1. 在 GTM 工作區中，點擊右上角的「**預覽**」按鈕
2. 在跳出的視窗中輸入 `https://www.movietribe.club/`，點擊「Connect」
3. 網站會在新視窗中開啟，同時 Tag Assistant 偵錯面板會在另一個分頁顯示

**預覽模式的關鍵檢查面板：**

| 面板標籤 | 顯示內容 | 你要觀察什麼 |
|----------|---------|-------------|
| Summary | 事件時間軸，列出所有已觸發的事件 | 左側時間軸上是否出現你預期的事件（如 Click） |
| Tags | 代碼觸發狀態 | `GA4 Event - click_recommendation` 是否出現在「Tags Fired」 |
| Variables | 各變數的即時數值 | `Click Text` 的值是否正確顯示為按鈕文字 |
| Data Layer | 資料層的內容 | 資料層是否有推送預期的資料 |

**步驟化的除錯流程：**

1. 進入預覽模式後，在 MovieTribe 網站上**執行目標行為**（例如點擊電影推薦按鈕）
2. 切換到 Tag Assistant 分頁，在左側時間軸找到對應的 **Click 事件**
3. 點擊該事件，切換到「**Tags**」標籤，確認你的代碼出現在「**Tags Fired**」區塊

   - 如果代碼出現在「**Tags Not Fired**」→ 問題在觸發條件，需要回去檢查篩選規則
   - 如果代碼出現在「**Tags Fired**」→ 觸發成功，繼續檢查參數

4. 點擊已觸發的代碼名稱，查看「**Values**」頁籤，確認事件名稱和參數值都正確

5. 切換到「**Variables**」標籤，確認各變數的實際值是否符合預期

### 5.2 GA4 DebugView 驗證

GTM 預覽模式確認代碼觸發後，下一步要到 GA4 的 **DebugView**（偵錯檢視）確認資料確實抵達 GA4。

**為什麼需要兩段驗證？**

```
GTM 預覽模式                    GA4 DebugView
──────────                     ──────────────
確認代碼「有沒有觸發」     →     確認資料「有沒有抵達」
（代碼層面的驗證）               （接收端的驗證）
```

就像寄包裹——GTM 預覽模式確認「包裹已寄出」，GA4 DebugView 確認「收件人收到了」。

**操作步驟：**

1. 開啟 [GA4 後台](https://analytics.google.com/)
2. 左側選單最下方，點擊「**管理**」（齒輪圖示）
3. 在「資源」欄位下方找到「**DebugView**」並點擊
4. 回到 MovieTribe 網站（保持 GTM 預覽模式開啟），執行目標行為
5. 在 GA4 DebugView 畫面中，觀察：

   | 觀察項目 | 預期結果 |
   |----------|---------|
   | 事件名稱是否出現 | 時間軸上出現 `click_recommendation` 事件 |
   | 點擊事件展開參數 | 包含 `click_text`、`button_id`、`page_location` 等參數 |
   | 參數值是否正確 | `click_text` 顯示實際按鈕文字，`page_location` 顯示正確頁面路徑 |

> DebugView 的資料顯示可能有 5-15 秒的延遲，如果沒有立即看到事件，請稍等一下再重新整理頁面。

### 5.3 常見除錯情境與排查清單

以下整理了最常遇到的除錯情境，按照排查順序逐一檢查：

**情境一：代碼沒有觸發（出現在 Tags Not Fired）**

| 排查順序 | 檢查項目 | 解決方式 |
|----------|---------|---------|
| 1 | 觸發條件類型是否正確 | 按鈕點擊應使用「點擊 - 所有元素」，而非「僅連結」 |
| 2 | 篩選條件的值是否正確 | 在 Variables 面板查看實際的 Click Text、Click ID 值 |
| 3 | 篩選條件的運算符是否正確 | 「等於」要求完全一致，「包含」則是部分匹配 |
| 4 | 是否有多個觸發條件衝突 | 確認代碼只綁定了一個正確的觸發條件 |

**情境二：代碼觸發了，但 GA4 DebugView 沒有資料**

| 排查順序 | 檢查項目 | 解決方式 |
|----------|---------|---------|
| 1 | Google 代碼是否正常運作 | 檢查 `Google Tag - GA4` 是否在 Tags Fired 中 |
| 2 | GA4 事件代碼的設定代碼是否正確 | 確認選擇了正確的 Google Tag |
| 3 | 是否有瀏覽器擴充套件阻擋 | 暫時停用廣告阻擋器（Ad Blocker）等擴充套件 |
| 4 | DebugView 是否等待足夠時間 | 等待 15-30 秒後重新整理 |

**情境三：參數值顯示不正確或為空**

| 排查順序 | 檢查項目 | 解決方式 |
|----------|---------|---------|
| 1 | 變數名稱拼寫是否正確 | 確認代碼中的 `{{變數名稱}}` 與實際變數名稱完全一致 |
| 2 | 變數在觸發時機是否有值 | 在 Variables 面板中查看該變數在觸發當下的值 |
| 3 | 自訂 JavaScript 變數是否有錯誤 | 開啟瀏覽器開發者工具（F12）的 Console，查看是否有 JavaScript 錯誤 |

## 8. FAQ — 常見問題

**Q1：自訂事件和建議事件有什麼差別？該怎麼選擇？**

**建議事件（Recommended Events）** 是 Google 官方預先定義的事件名稱，如 `sign_up`、`share`、`purchase` 等。使用建議事件的好處是 GA4 報表中可能會有預設的分析功能支援。**自訂事件**則是完全由你定義的事件名稱，適用於 Google 建議清單中沒有涵蓋的追蹤需求。原則上：如果 Google 建議清單中有適合的事件名稱，優先使用建議事件；如果沒有，再建立自訂事件。

**Q2：事件名稱可以用中文嗎？**

不行。GA4 事件名稱只能使用英文字母、數字和底線。中文字元會導致事件無法被正確記錄。參數的「值」（Value）可以包含中文，但參數「名稱」（Name）同樣只能使用英文字母、數字和底線。

**Q3：每個事件最多 25 個參數，會不會不夠用？**

對大多數情境來說綽綽有餘。實務上，一個事件通常只需要 3-5 個參數就能涵蓋核心分析需求。與其塞滿參數，不如思考「哪些資訊真的會用在報表分析中」，只傳遞有價值的參數。

**Q4：我在預覽模式中看到代碼觸發了，為什麼 GA4 即時報表看不到？**

即時報表（Realtime Report）和 DebugView 是不同的功能。在 GTM 預覽模式下，資料會優先送到 DebugView 而非即時報表。如果要在即時報表中看到資料，需要關閉 GTM 預覽模式，以正常模式瀏覽網站。建議測試階段使用 DebugView，發布後再透過即時報表確認。

**Q5：觸發條件用 Click Text 還是 Click ID 比較好？**

各有優缺點：

| 篩選方式 | 優點 | 缺點 |
|----------|------|------|
| Click Text | 直觀易懂，不需看原始碼 | 如果按鈕文字被修改，觸發條件會失效 |
| Click ID | 穩定性高，不會因文字變動而失效 | 需要查看 HTML 原始碼取得 ID，且不是每個元素都有 ID |
| Click Classes | 彈性最高，可同時匹配多個元素 | Class 可能因為改版而變更 |

建議優先使用 Click ID（如果元素有 ID），其次是 Click Classes，最後才用 Click Text。

**Q6：我建了多個事件代碼，要一次發布還是分批發布？**

建議**逐一測試、分批發布**。每建立一個事件代碼，就用預覽模式測試一次，確認正確後再發布一個版本。這樣如果出問題，能快速定位是哪個代碼造成的。一次發布太多未經測試的變更，出錯時排查會非常困難。

**Q7：自訂事件需要在 GA4 中額外註冊嗎？**

自訂事件本身不需要額外註冊，GTM 發送後 GA4 會自動接收。但如果你想讓事件的自訂參數出現在 GA4 的標準報表中，需要在 GA4 後台將參數「註冊」為自訂維度（Custom Dimensions）或自訂指標（Custom Metrics）。這部分我們會在 Week 6 詳細學習。
