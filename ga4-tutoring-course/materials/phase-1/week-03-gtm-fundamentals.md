## 3. 核心概念：三大組件詳解

### 3.1 總覽：一句話理解三者關係

GTM 的運作邏輯可以濃縮成一句話：

> **當「觸發條件」被滿足時，執行「代碼」，並利用「變數」傳遞詳細資訊。**

用生活情境來類比：

| GTM 組件 | 類比角色 | 做的事情 |
|----------|---------|---------|
| 代碼（Tags） | 快遞員 | 負責把包裹送到指定地點（例如把資料送到 GA4） |
| 觸發條件（Triggers） | 出發指令 | 告訴快遞員「什麼時候出發」（例如客人按了下單鍵） |
| 變數（Variables） | 包裹上的資訊 | 包裹裡的詳細內容（收件人、品項、金額） |

串起來就是：**當客人按了下單鍵（觸發條件）→ 快遞員出發（代碼執行）→ 帶著訂單明細（變數）送到倉庫（GA4）。**

### 3.2 代碼 Tags — 定義「要做什麼」

**代碼（Tags）** 是 GTM 裡的「行動者」，負責執行特定任務。

常見的代碼類型：

| 代碼類型 | 功能說明 | 對應場景 |
|----------|---------|---------|
| Google 代碼（Google Tag） | 建立與 GA4 的連線基礎 | 網站載入時發送基礎數據 |
| GA4 事件代碼 | 發送特定事件到 GA4 | 追蹤按鈕點擊、表單送出 |
| Google Ads 轉換代碼 | 回傳廣告轉換資料 | 購買完成頁面回傳 |
| 自訂 HTML 代碼 | 執行任意 HTML/JavaScript | 安裝第三方工具（如聊天機器人） |

重點觀念：

- 一個 GTM 容器（Container）中可以有**多個代碼**
- 每個代碼必須搭配**至少一個觸發條件**才能運作
- 代碼本身不會自己啟動，它需要觸發條件來「叫醒」它

### 3.3 觸發條件 Triggers — 定義「何時做」

**觸發條件（Triggers）** 是 GTM 的「啟動器」，決定代碼在什麼時機點執行。

你可以把觸發條件想像成鬧鐘或交通號誌——時間到了鬧鐘響起（代碼執行），或者看到綠燈亮了才通行。

常見的觸發條件類型：

| 觸發條件 | 觸發時機 | MovieTribe 應用範例 |
|----------|---------|-------------------|
| 頁面瀏覽（Page View） | 網頁載入完成 | 使用者打開任一電影介紹頁 |
| 點擊（Click） | 使用者點擊特定元素 | 點擊「加入收藏」按鈕 |
| 捲動深度（Scroll Depth） | 頁面捲動達到指定比例 | 讀者往下滾動到文章 75% 處 |
| 表單送出（Form Submission） | 表單成功提交 | 使用者送出會員註冊表 |
| 計時器（Timer） | 頁面停留達到指定秒數 | 使用者在頁面停留超過 30 秒 |
| 自訂事件（Custom Event） | 由程式碼手動推送 | 影片播放達特定進度 |

觸發條件的組成結構：

```
觸發條件 = 觸發類型 + 篩選規則
```

例如：「使用者點擊 class 為 `btn-favorite` 的按鈕」這個觸發條件，由「點擊」觸發類型加上「Click Classes 等於 btn-favorite」篩選規則組成。

### 3.4 變數 Variables — 定義「詳細資訊」

**變數（Variables）** 是 GTM 的「資訊包」，用來儲存和傳遞各種動態數值。

變數分為兩大類：

**內建變數（Built-in Variables）**

GTM 預先定義好的變數，啟用後即可使用：

| 變數名稱 | 取得的資訊 | 範例值 |
|----------|----------|--------|
| Page URL | 目前頁面的完整網址 | `https://www.movietribe.club/movies/inception` |
| Page Path | 目前頁面的路徑 | `/movies/inception` |
| Page Title | 目前頁面的標題 | `全面啟動 - MovieTribe` |
| Click Text | 被點擊元素的文字 | `加入收藏` |
| Click URL | 被點擊連結的網址 | `https://www.movietribe.club/favorites` |
| Scroll Depth Threshold | 捲動深度的百分比 | `75` |

**使用者定義變數（User-Defined Variables）**

根據需求自行建立的變數，常見類型包含：

- **資料層變數（Data Layer Variable）**：從資料層取得指定欄位的值
- **常數（Constant）**：固定不變的值（例如 GA4 的 Measurement ID）
- **JavaScript 變數**：透過自訂 JavaScript 計算取得的值

### 3.5 三者聯動的完整邏輯

用一張流程圖來看三者如何協作：

```
使用者行為（例如點擊按鈕）
        │
        ▼
┌──────────────────┐
│   觸發條件判斷     │  ← 使用者點了什麼？符合篩選規則嗎？
│   (Trigger)       │
└────────┬─────────┘
         │ 條件滿足 ✓
         ▼
┌──────────────────┐
│   執行代碼        │  ← 發送事件到 GA4
│   (Tag)           │
└────────┬─────────┘
         │ 需要附帶資訊
         ▼
┌──────────────────┐
│   變數提供資訊     │  ← 頁面標題、按鈕文字、頁面路徑⋯
│   (Variable)      │
└──────────────────┘
```

**具體範例：追蹤 MovieTribe 的「加入收藏」按鈕點擊**

1. 使用者在電影頁面點擊「加入收藏」按鈕
2. **觸發條件**判斷：觸發類型是「點擊」，篩選規則為 Click Text 等於「加入收藏」→ 條件滿足
3. **代碼**啟動：GA4 事件代碼執行，發送一筆 `add_to_favorites` 事件到 GA4
4. **變數**提供細節：事件參數包含 `movie_title`（變數：Page Title）與 `page_path`（變數：Page Path）

## 4. 資料層 Data Layer 概念介紹

### 什麼是資料層？

**資料層（Data Layer）** 是一個結構化的 JavaScript 物件，扮演網站與 GTM 之間的「資料橋樑」。

### 抽屜類比

把資料層想像成一組**透明抽屜櫃**：

1. **網站把資料放進抽屜**：後端或前端程式碼將資訊（如會員等級、電影類別）存入資料層
2. **GTM 打開抽屜取資料**：GTM 透過「資料層變數」讀取抽屜裡的內容
3. **貼在標籤上寄出去**：把取得的資料附加在代碼的事件參數中，發送到 GA4

```
網站程式碼                    GTM                        GA4
───────────                 ─────                      ────
把資料放進抽屜  ──→  打開抽屜取出資料  ──→  貼在標籤上寄出
(dataLayer.push)    (Data Layer Variable)    (Event Parameter)
```

### 資料層長什麼樣子？

資料層本質上是一個 JavaScript 陣列，裡面裝著一個個 JSON 物件：

```javascript
// 網站程式碼將資訊推入資料層
dataLayer.push({
  'event': 'movie_view',
  'movie_title': '全面啟動',
  'movie_genre': '科幻',
  'user_membership': 'premium'
});
```

上面這段程式碼的意思是：「有人瀏覽了一部電影，片名是全面啟動，類型是科幻，這位使用者是 premium 會員。」

GTM 收到後，就能用資料層變數取出 `movie_title`、`movie_genre`、`user_membership` 這些值，再透過代碼發送到 GA4。

### 什麼時候需要用到資料層？

| 情境 | 說明 |
|------|------|
| 內建變數不夠用 | 想追蹤的資訊（如會員等級、商品價格）無法從頁面 DOM 直接取得 |
| 需要後端資料 | 某些資料只有伺服器端知道（如訂單編號、折扣碼） |
| 資料格式要統一 | 確保 GTM 讀到的資料格式一致，避免抓取錯誤 |

> 本週只需理解資料層的概念，後續 Week 5 會實際操作資料層的應用。

## 5. GTM 介面操作與版本控制

### 5.1 工作區 Workspace

**工作區（Workspace）** 是 GTM 中進行修改的獨立空間。

你可以把工作區想像成 Google Docs 的「建議模式」——所有修改都先存在草稿中，不會立刻影響正式環境，直到你按下「發布」。

關鍵概念：

- 免費版 GTM 提供 3 個工作區
- **預設工作區**（Default Workspace）是最常使用的
- 每次修改都在工作區中進行，不會立刻生效
- 發布後，工作區的變更才會套用到正式網站

### 5.2 預覽模式 Preview Mode

**預覽模式（Preview Mode）** 是 GTM 提供的即時測試工具，讓你在發布前驗證代碼是否正確運作。

進入預覽模式後，GTM 會開啟一個名為 **Tag Assistant** 的偵錯面板，顯示：

| 面板資訊 | 說明 |
|----------|------|
| Tags Fired | 已觸發的代碼清單（代表設定正確） |
| Tags Not Fired | 未觸發的代碼清單（需檢查觸發條件） |
| Data Layer | 當下資料層中的所有資料 |
| Variables | 各變數在觸發當下的數值 |

使用預覽模式的步驟：

1. 在 GTM 工作區中點擊右上角的「預覽」按鈕
2. 輸入你要測試的網址（例如 `https://www.movietribe.club/`）
3. 系統會開啟新視窗載入你的網站，同時底部出現 Tag Assistant 偵錯面板
4. 在網站上進行操作（點擊、捲動等），觀察 Tag Assistant 的反應

### 5.3 版本控制與發布流程

GTM 的版本控制機制就像存檔系統——每次發布都會建立一個版本快照（Snapshot），讓你隨時可以回溯。

**發布流程：**

```
修改代碼/觸發條件/變數
        │
        ▼
  使用預覽模式測試
        │
        ▼
    測試通過？
   ╱        ╲
  否          是
  │           │
  ▼           ▼
回去修改    點擊「提交」
              │
              ▼
        填寫版本名稱與說明
              │
              ▼
         選擇「發布」
              │
              ▼
        版本正式上線
```

**版本管理的好習慣：**

| 習慣 | 說明 | 範例 |
|------|------|------|
| 有意義的版本名稱 | 描述這次發布做了什麼 | `v3 - 新增 GA4 基礎代碼` |
| 填寫版本說明 | 記錄修改內容與原因 | `安裝 Google 代碼，觸發條件為 All Pages` |
| 測試後再發布 | 永遠先用預覽模式驗證 | — |
| 小步快跑 | 每次只修改一小部分就發布 | 避免一次改太多難以排錯 |

## 6. 實作步驟

### 6.1 啟用內建變數

GTM 預設只啟用少數幾個內建變數，我們需要手動開啟更多常用的變數。

**操作步驟：**

1. 登入 [GTM 後台](https://tagmanager.google.com/)
2. 進入 MovieTribe 的 GTM 容器
3. 左側選單點擊「**變數**」
4. 在「內建變數」區塊，點擊右上角的「**設定**」
5. 勾選以下常用變數：

| 類別 | 勾選項目 | 用途 |
|------|---------|------|
| 頁面 | Page URL、Page Path、Page Title、Referrer | 追蹤頁面資訊與流量來源 |
| 點擊 | Click Element、Click Classes、Click ID、Click URL、Click Text | 追蹤使用者點擊行為 |
| 表單 | Form Element、Form Classes、Form ID、Form URL、Form Text | 追蹤表單互動 |
| 捲動 | Scroll Depth Threshold、Scroll Depth Units、Scroll Direction | 追蹤閱讀深度 |

6. 完成勾選後，這些變數就會出現在內建變數清單中

### 6.2 建立第一個 Google 代碼

**Google 代碼（Google Tag）** 是 GA4 資料收集的基礎，負責建立網站與 GA4 之間的連線。

**操作步驟：**

1. 左側選單點擊「**代碼**」→ 點擊「**新增**」
2. 點擊「代碼設定」區塊 → 選擇代碼類型「**Google 代碼**」
3. 在「代碼 ID」欄位輸入你的 GA4 Measurement ID（格式：`G-XXXXXXXXXX`）
4. 點擊「觸發條件」區塊 → 選擇「**Initialization - All Pages**」

   > 為什麼選 Initialization - All Pages？
   >
   > 這個觸發條件會在頁面載入的**最早階段**觸發，確保 GA4 的基礎連線在所有其他代碼之前建立。這樣後續的 GA4 事件代碼才能正確運作。

5. 將代碼命名為 `Google Tag - GA4`（建議採用「代碼類型 - 用途」的命名格式）
6. 點擊右上角「**儲存**」

### 6.3 使用預覽模式驗證

代碼建立完成後，先別急著發布，用預覽模式確認一切正常。

**驗證步驟：**

1. 點擊 GTM 右上角的「**預覽**」按鈕
2. 在跳出的視窗中輸入 `https://www.movietribe.club/`，點擊「Connect」
3. 網站會在新視窗中開啟，同時出現 Tag Assistant 偵錯面板
4. 檢查以下項目：

| 檢查項目 | 預期結果 | 異常處理 |
|----------|---------|---------|
| Tag Assistant 是否成功連線 | 顯示「Connected」 | 確認 GTM 程式碼已正確安裝在網站上 |
| Google Tag - GA4 是否出現在 Tags Fired | 出現在已觸發清單 | 檢查觸發條件是否設為 Initialization - All Pages |
| Initialization 事件中是否包含此代碼 | 代碼列在 Initialization 事件下 | 確認代碼類型選擇正確 |

5. 確認一切正常後，關閉預覽模式
6. 點擊右上角「**提交**」→ 填寫版本名稱（例如 `v1 - 安裝 Google 代碼`）→ 點擊「**發布**」

## 7. MovieTribe 實際操作情境

以下是 MovieTribe 網站未來可以運用 GTM 三大組件追蹤的實際情境。本週先理解概念，後續幾週會逐步實作。

### 情境一：追蹤電影頁面瀏覽

> 「我想知道哪些電影頁面最多人看。」

| 組件 | 設定 |
|------|------|
| 代碼 | GA4 事件代碼，發送 `page_view` 事件 |
| 觸發條件 | 頁面瀏覽，篩選 Page Path 開頭為 `/movies/` |
| 變數 | Page Title（取得電影名稱）、Page Path（取得電影路徑） |

### 情境二：追蹤文章閱讀深度

> 「我想知道部落格文章有多少人真的讀完。」

| 組件 | 設定 |
|------|------|
| 代碼 | GA4 事件代碼，發送 `scroll` 事件 |
| 觸發條件 | 捲動深度達 25%、50%、75%、100%，篩選 Page Path 開頭為 `/blog/` |
| 變數 | Scroll Depth Threshold（捲動百分比）、Page Title（文章標題） |

### 情境三：追蹤社群分享按鈕

> 「我想知道訪客有沒有把電影推薦分享出去。」

| 組件 | 設定 |
|------|------|
| 代碼 | GA4 事件代碼，發送 `share` 事件 |
| 觸發條件 | 點擊，篩選 Click Classes 包含 `share-btn` |
| 變數 | Click Text（分享平台名稱）、Page Title（分享的電影名稱） |

> 以上情境僅為規劃範例。實際的 CSS Class 名稱與頁面結構需要檢視 MovieTribe 網站原始碼後才能確認。

## 9. FAQ — 常見問題

**Q1：代碼、觸發條件、變數一定要三個同時存在嗎？**

代碼和觸發條件是必要的搭配——沒有觸發條件的代碼永遠不會執行。變數則是選用的，如果代碼不需要額外的動態資訊，可以不使用變數。但實務上大多數情境都會用到變數來傳遞頁面資訊或事件參數。

**Q2：Google 代碼和 GA4 事件代碼有什麼不同？**

**Google 代碼**（Google Tag）是基礎建設，負責建立網站與 GA4 之間的連線，每個頁面載入時都會執行。**GA4 事件代碼**（GA4 Event Tag）則是在特定行為發生時，透過已建立的連線發送事件資料。Google 代碼就像先把電話線牽好，GA4 事件代碼則是實際撥打電話傳遞訊息。

**Q3：預覽模式只有我自己看得到嗎？會影響正式網站嗎？**

是的，預覽模式只在你的瀏覽器中運作，其他使用者不會受到影響。它是一個安全的測試環境，你可以放心地反覆測試。

**Q4：發布後發現設定有誤怎麼辦？**

GTM 的版本控制讓你可以隨時回溯。在 GTM 後台的「版本」頁面，找到上一個正確的版本，點擊「發布」即可回復。這也是為什麼建議每次發布都寫清楚版本說明的原因。

**Q5：資料層需要我自己寫程式碼嗎？**

是的，資料層的推送（`dataLayer.push`）需要由網站開發端實作。如果你不會寫程式碼，通常需要請工程師協助。不過別擔心，本週只需理解概念，許多基礎追蹤透過 GTM 的內建變數就能完成，不一定需要資料層。

**Q6：內建變數和自訂變數哪個優先使用？**

優先使用內建變數。內建變數由 GTM 官方維護、穩定可靠、設定簡單。只有在內建變數無法取得你需要的資訊時（例如會員等級、自訂分類），才需要建立自訂變數。
