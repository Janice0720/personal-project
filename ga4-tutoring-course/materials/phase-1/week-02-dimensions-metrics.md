## 3. 核心概念一：維度——報表的「分類標籤」

### 3-1. 白話定義

**維度（Dimensions）** 就是用來「描述」資料的標籤，它告訴你「這筆資料是什麼類型的」。

### 3-2. 生活類比：圖書館的分類標籤

想像你走進一間圖書館。每一本書上面都貼了好幾張分類標籤：

| 標籤類別 | 標籤內容 | 對應 GA4 維度 |
|----------|----------|---------------|
| 書籍類型 | 小說、科普、傳記 | 事件名稱（Event name） |
| 所屬樓層 | 1F、2F、3F | 頁面路徑（Page path） |
| 語言 | 中文、英文、日文 | 語言（Language） |
| 出版社 | 遠流、天下、商周 | 來源/媒介（Source / Medium） |

這些標籤本身不是數字，而是「文字」或「類別」。它們的作用是讓你可以**分組**和**篩選**。

例如你可以說：「我想看 2F 的英文科普書」——這就是同時用了三個維度在篩選。

### 3-3. GA4 中常見的維度

| 維度名稱 | 說明 | 範例值 |
|----------|------|--------|
| 城市（City） | 使用者所在城市 | Taipei、Tokyo、New York |
| 裝置類別（Device category） | 使用的裝置類型 | desktop、mobile、tablet |
| 來源/媒介（Source / Medium） | 流量從哪裡來 | google / organic、facebook / cpc |
| 事件名稱（Event name） | 觸發了什麼事件 | page_view、scroll、click |
| 頁面路徑（Page path） | 瀏覽了哪個頁面 | /、/about、/blog/article-1 |

### 3-4. 維度在報表中的位置

維度通常出現在報表的**列（Rows）**，也就是表格最左邊那一欄。它們負責「分組」，讓你知道每一行代表的是哪一類資料。

```
┌──────────────────┬──────────┬──────────┐
│   維度（Rows）    │  指標 A   │  指標 B   │
├──────────────────┼──────────┼──────────┤
│ google / organic │   1,200  │   3.5%   │
│ facebook / cpc   │     450  │   2.1%   │
│ direct / (none)  │     800  │   4.2%   │
└──────────────────┴──────────┴──────────┘
       ↑ 文字/類別        ↑ 數字/百分比
```

## 4. 核心概念二：指標——報表的「衡量數字」

### 4-1. 白話定義

**指標（Metrics）** 就是用來「計算」資料的數值，它回答的是「有多少？多大？多快？」這類問題。

### 4-2. 生活類比：圖書館的營運數據

繼續用圖書館的例子。如果維度是書上的「分類標籤」，那指標就是圖書館的「營運數據」：

| 營運數據 | 問的問題 | 對應 GA4 指標 |
|----------|----------|---------------|
| 今天有多少人進館？ | 多少人？ | 活躍使用者（Active users） |
| 今天一共借了幾本書？ | 幾次？ | 事件計數（Event count） |
| 平均每人待了多久？ | 多久？ | 平均參與時間（Average engagement time） |
| 每人平均借幾本？ | 比率？ | 每位使用者事件數（Events per user） |
| 有多少人辦了借書證？ | 轉換？ | 轉換（Conversions） |

指標永遠是**數字**：可以是整數（1,200 人）、小數（3.5 分鐘）、百分比（45.2%）或金額（$1,500）。

### 4-3. GA4 中常見的指標

| 指標名稱 | 說明 | 範例值 |
|----------|------|--------|
| 活躍使用者（Active users） | 有互動行為的不重複使用者數 | 1,200 |
| 事件計數（Event count） | 事件被觸發的總次數 | 15,600 |
| 參與率（Engagement rate） | 有參與的工作階段占比 | 62.3% |
| 平均參與時間（Average engagement time） | 每次工作階段的平均互動時長 | 2m 35s |
| 收益（Revenue） | 電商交易的總金額 | $4,500 |

### 4-4. 指標在報表中的位置

指標通常出現在報表的**值（Values）**或**欄（Columns）**，也就是表格中間和右邊的數字區域。

## 5. 維度 vs 指標：一張表看懂差異

| 比較項目 | 維度（Dimensions） | 指標（Metrics） |
|----------|-------------------|-----------------|
| 本質 | 描述性屬性、標籤 | 量化衡量、數值 |
| 回答什麼 | 「是什麼？」「哪一種？」 | 「有多少？」「多大？」 |
| 資料類型 | 文字 / 類別 | 數字 / 百分比 |
| 報表位置 | 列（Rows） | 值（Values）/ 欄（Columns） |
| 類比 | 圖書館的書籍標籤 | 圖書館的營運數據 |
| 操作方式 | 用來分組、篩選 | 用來加總、平均、比較 |

**一句話記住：** 維度告訴你「看的是誰」，指標告訴你「數字是多少」。

## 6. 核心概念三：範圍——決定數據歸屬的「層級」

### 6-1. 為什麼需要了解範圍？

在 GA4 中，每一個維度和指標都有自己的「範圍（Scope）」。範圍決定了這筆資料是在描述「誰」或「什麼層級」的事情。

如果你把不同範圍的維度和指標混在一起看，就會得到**錯誤或無意義的數據**。這是初學者最容易踩的坑。

### 6-2. 生活類比：公司的組織層級

想像一間公司有三個層級的資訊：

```
┌──────────────────────────────────────────────────┐
│  公司層級（≈ 使用者範圍 User-scoped）              │
│  公司名稱、產業類別、成立年份                        │
│                                                    │
│  ┌──────────────────────────────────────────┐     │
│  │  部門層級（≈ 工作階段 Session-scoped）      │     │
│  │  部門名稱、部門人數                         │     │
│  │                                            │     │
│  │  ┌──────────────────────────────────┐     │     │
│  │  │  員工層級（≈ 事件範圍 Event-scoped）│     │     │
│  │  │  員工姓名、今天的出勤紀錄          │     │     │
│  │  └──────────────────────────────────┘     │     │
│  └──────────────────────────────────────────┘     │
└──────────────────────────────────────────────────┘
```

- **公司層級**的資訊（如產業類別）是長期不變的，適用於整間公司
- **部門層級**的資訊（如部門人數）在一段期間內有效
- **員工層級**的資訊（如今天有沒有出勤）只和當下那一刻有關

你不會拿「員工 A 今天有出勤」來代表「整間公司的出勤狀況」，對吧？在 GA4 裡也是一樣的道理。

### 6-3. GA4 的三大範圍

| 範圍 | 說明 | 代表意義 | 範例維度 |
|------|------|----------|----------|
| **使用者範圍（User-scoped）** | 記錄使用者的長期屬性 | 「這個人是誰」 | 首次造訪來源、使用者年齡層、國家 |
| **事件範圍（Event-scoped）** | 只關注某一次行為當下 | 「這一刻發生了什麼」 | 事件名稱、頁面標題、頁面路徑 |
| **商品範圍（Item-scoped）** | 電商交易中的商品細節 | 「買了什麼東西」 | 商品名稱、商品類別、商品品牌 |

### 6-4. 範圍搭配錯誤的後果

**錯誤範例：** 把「使用者的首次造訪來源」和「單次事件的頁面路徑」混在一起做交叉分析。

這就像在問：「公司成立年份為 2020 年的公司，今天員工 A 出勤了嗎？」——問題邏輯上可以成立，但如果你想用這個結果來推論「2020 年成立的公司出勤率比較高」，就會產生嚴重誤導。

**正確原則：**
- 使用者範圍的維度 搭配 使用者範圍的指標
- 事件範圍的維度 搭配 事件範圍的指標
- 如果不確定，先查 [GA4 維度與指標官方文件](https://support.google.com/analytics/answer/9143382?hl=zh-Hant) 確認範圍

> 小提醒：GA4 的探索報表（Explorations）在你嘗試混用不同範圍時，有時候會直接不顯示資料，或是呈現灰色不可選取。這其實是 GA4 在保護你，避免產出無意義的報表。

## 7. 核心概念四：高基數——當分類標籤太多時的 `(other)` 問題

### 7-1. 什麼是高基數？

**高基數（High-cardinality）** 指的是一個維度擁有「極大量的唯一值」。

### 7-2. 生活類比：信箱裡的分類資料夾

假設你的 Email 信箱有分類資料夾：

- **低基數**的分類方式：「工作」「個人」「廣告」——只有 3 個資料夾，管理很輕鬆
- **高基數**的分類方式：為每一封信都建一個專屬資料夾，例如「2026-03-01-王小明-會議通知」——幾千個資料夾，根本無法管理

在 GA4 裡也是如此。如果一個維度的唯一值太多（例如把完整的網址含查詢參數當維度），GA4 會無法有效處理。

### 7-3. GA4 的處理方式：`(other)` 列

當一個維度的唯一值超過 GA4 的處理上限，系統會自動把排名較後面的值全部壓縮進一個叫做 **`(other)`** 的集合。

```
報表原本應該顯示：
  頁面路徑           活躍使用者
  /home              1,200
  /blog/article-1      300
  /blog/article-2      280
  /blog/article-3      250
  ...
  /blog/article-9999     1

GA4 實際顯示（高基數情況下）：
  頁面路徑           活躍使用者
  /home              1,200
  /blog/article-1      300
  /blog/article-2      280
  ...（前 N 名）
  (other)            5,600    ← 其餘數千筆被合併在這裡
```

### 7-4. 為什麼這很重要？

- 你可能**找不到**你想看的那筆資料，因為它被吞進 `(other)` 了
- `(other)` 裡面的數據**無法進一步拆解**，等於那些資料對你來說「消失了」
- 這個問題在**自訂維度（Custom dimensions）**上特別嚴重，因為你可能不小心建了一個唯一值爆量的維度

### 7-5. 如何避免高基數問題？

| 做法 | 說明 |
|------|------|
| 使用分類而非明細 | 用「文章類別」而非「文章完整標題」作為維度 |
| 避免含動態參數的網址 | `/blog?id=12345` 應該清理成 `/blog` |
| 控制自訂維度數量 | GA4 免費版的自訂維度有數量上限（事件範圍 50 個、使用者範圍 25 個） |
| 善用 GA4 的內建維度 | 優先使用 GA4 已經提供的維度，減少自建需求 |

## 8. 實作練習：GA4 Demo Account 數據檢索

以下練習全部使用 Google 提供的 GA4 示範帳戶（Google Merchandise Store）。

### 練習 1：辨識標準報表中的維度與指標

**目標：** 在標準報表中正確指出哪些是維度、哪些是指標。

**步驟：**

1. 進入 GA4 示範帳戶
2. 左側選單點擊「報表」→「生命週期」→「流量開發」→「流量開發」
3. 觀察報表內容，回答以下問題：

| 題目 | 你的答案 |
|------|----------|
| 報表最左邊一欄（預設分組依據）是什麼？它是維度還是指標？ | |
| 「使用者」欄位顯示的是數字。它是維度還是指標？ | |
| 「工作階段」欄位呢？ | |
| 「參與率」呢？ | |

### 練習 2：切換維度觀察數據變化

**目標：** 體驗「維度就是分組方式」這件事。

**步驟：**

1. 同樣在「流量開發」報表
2. 點擊報表上方的維度下拉選單（預設可能是「工作階段預設頻道分組」）
3. 嘗試切換為：
   - 「工作階段來源/媒介」
   - 「工作階段來源平台」
4. 觀察：**指標的數字總和有沒有改變？分組方式有什麼不同？**

> 關鍵發現：切換維度時，數據的「總量」通常不變，但「怎麼分組」改變了。就像同一批書，你可以按「語言」分，也可以按「出版社」分，書的總數不會變。

### 練習 3：在探索報表中體驗範圍限制

**目標：** 親眼看到 GA4 如何阻止你混用不同範圍。

**步驟：**

1. 左側選單點擊「探索」
2. 點擊「空白」建立一個新的探索報表
3. 在「維度」區塊，點擊「+」加入一個維度：選擇「事件名稱」
4. 在「指標」區塊，點擊「+」加入一個指標：選擇「活躍使用者」
5. 將維度拖到「列」，將指標拖到「值」
6. 觀察報表是否正常顯示
7. 接著嘗試加入不同範圍的組合，注意是否有欄位變灰或數據顯示異常

## 9. MovieTribe 應用情境

以下用 [MovieTribe](https://www.movietribe.club/) 網站的實際場景，幫助你將抽象概念對應到自己的業務。

### 情境 1：哪些是你網站上的「維度」？

想像 MovieTribe 已經正確安裝 GA4，以下是可能收集到的維度：

| 維度 | MovieTribe 的實際範例 |
|------|----------------------|
| 頁面路徑（Page path） | `/`、`/movies/inception`、`/reviews/latest` |
| 來源/媒介（Source / Medium） | `google / organic`、`instagram / social`、`line / referral` |
| 裝置類別（Device category） | `mobile`（手機）、`desktop`（桌電） |
| 國家（Country） | `Taiwan`、`Hong Kong`、`Japan` |
| 事件名稱（Event name） | `page_view`、`scroll`、`click`、`share_movie` |

### 情境 2：哪些是你最該關注的「指標」？

| 指標 | 對 MovieTribe 的意義 |
|------|---------------------|
| 活躍使用者（Active users） | 有多少人實際在使用你的網站？社群有多熱絡？ |
| 參與率（Engagement rate） | 來的人有沒有真的在看內容？還是一進來就離開了？ |
| 平均參與時間（Avg. engagement time） | 訪客平均花多少時間在你的網站上？時間越長代表內容越吸引人 |
| 每位使用者瀏覽量（Views per user） | 平均每個人看了幾個頁面？ |
| 事件計數（Event count） | 特定互動（例如分享電影、撰寫評論）發生了幾次？ |

### 情境 3：範圍的實際應用

假設你想回答這個問題：**「從 Instagram 來的使用者，最常看哪些電影頁面？」**

正確的做法是：
- **維度 1**（使用者/工作階段範圍）：來源 = Instagram
- **維度 2**（事件範圍）：頁面路徑
- **指標**：瀏覽次數

錯誤的做法是：
- 用「使用者的首次造訪來源 = Instagram」去比對「單次事件的頁面路徑」，然後試圖推論「Instagram 帶來的使用者都喜歡看恐怖片」——因為使用者的首次造訪來源只記錄第一次來的管道，後續造訪可能是從 Google 搜尋進來的。

### 情境 4：高基數對 MovieTribe 的影響

如果你把「完整的頁面網址（含查詢參數）」當作維度：

```
/movies/inception
/movies/inception?utm_source=ig&utm_medium=social&utm_campaign=winter2026
/movies/inception?ref=homepage_banner
/movies/inception?fbclid=abc123xyz
```

以上其實都是同一個頁面，但 GA4 會視為四筆不同的維度值。當這種情況大量發生，你的「頁面」維度就會產生高基數問題，真正有用的數據被稀釋或被丟進 `(other)`。

**解決方式：** 在 GA4 管理介面中排除不必要的查詢參數，或使用 GTM 在追蹤時就清理網址。

## 11. FAQ 常見問題

### Q1：維度和指標的數量有上限嗎？

**有。** GA4 免費版的自訂維度上限如下：
- 事件範圍自訂維度：50 個
- 使用者範圍自訂維度：25 個
- 自訂指標：50 個

但 GA4 本身提供的**內建維度和指標不受此限制**，所以應該優先使用內建的。

### Q2：我在報表中看到 `(not set)`，這是什麼意思？

`(not set)` 代表 GA4 沒有收到該維度的資料。常見原因包括：
- 追蹤代碼設定不完整
- 某些事件本身不帶有該維度的資訊
- 使用者的瀏覽器阻擋了某些資料的傳送

### Q3：`(other)` 和 `(not set)` 有什麼不同？

| 項目 | `(other)` | `(not set)` |
|------|-----------|-------------|
| 原因 | 唯一值太多，GA4 主動合併 | 該維度從未收到資料 |
| 是否有數據 | 有，只是被打包在一起 | 真的沒有資料 |
| 解決方式 | 減少維度的唯一值數量 | 檢查追蹤代碼設定 |

### Q4：我能不能在一個報表中同時用很多維度？

可以，但要注意：
- 維度越多，報表的列數就越多，數據會被拆分得很細
- 太多維度 + 太少的資料量 = 很多列只有個位數，統計上不具參考價值
- 建議從 1-2 個維度開始，有具體問題再逐步增加

### Q5：範圍搭配錯誤時 GA4 會報錯嗎？

不一定。在標準報表中，GA4 已經幫你配好了合理的組合，你不太會遇到。但在**探索報表（Explorations）**中，如果你拖入不相容的維度和指標，可能會看到：
- 欄位變灰無法選取
- 數據顯示為空白
- 數據出現但數值不合邏輯（這是最危險的情況）
