# A12 論文問答：白話解析
**論文**：鄭婕妤（2010）基於 RFM 分析法之顧客適性化產品推薦機制

---

## Q1：SOM 自組織映射圖網路是怎麼建成的？什麼是高維顧客？為什麼要映射到二維？又怎麼判斷兩個顧客「行為相似」？

### 什麼是「高維顧客」？

每位顧客都可以用好幾個數字來描述，例如：
- R = 最近一次購買距今幾天
- F = 過去一年買了幾次
- M = 過去一年花了多少錢

如果顧客有 3 個指標，就是「3 維」；如果還加上購買品項種類數、退貨次數、會員年資……，可能就有 10 幾維。**維度 = 描述顧客的指標數量。** 維度越高，資料越複雜、越難直觀理解。

---

### 為什麼要從高維映射到二維？

想像你有 1,000 位顧客，每人有 10 個特徵。這個資料存在「10 維空間」，你沒辦法畫出來、也很難看出誰跟誰像。

**SOM 的功用**就是把這個高維空間「壓縮」成一張二維地圖（像一個棋盤格），讓你可以：
- 眼睛看得見誰跟誰靠近
- 靠近的格子 = 行為相似的顧客

**關鍵保證**：SOM 壓縮時會盡量維持原本的相對距離——原本在高維空間很像的顧客，在二維地圖上也會被放在鄰近的位置。

---

### SOM 網路是怎麼「建成」的？（白話流程）

**第一步：鋪好棋盤**

先建立一個二維網格（例如 8×8 = 64 個節點），每個節點都是一個「虛擬顧客」，帶有跟真實顧客一樣多的特徵維度，一開始這些特徵是隨機初始化的數字。

**第二步：丟入一位真實顧客，找最像的節點**

把一位真實顧客的資料向量丟進去，看哪個節點跟他「最像」（用歐式距離計算：特徵差距最小的那個節點）。找到的那個節點叫做 **BMU（Best Matching Unit，最佳匹配節點）**。

**第三步：BMU 及其鄰居向這位顧客「靠近」**

BMU 的特徵值往這位顧客稍微調整，它周圍的節點也跟著調整（但幅度較小）。就像在地圖上「吸引」附近地區往這位顧客的方向移動。

**第四步：重複所有顧客，反覆訓練**

把所有顧客一輪一輪地餵進去，每次都重複「找 BMU → 更新節點」的動作。訓練幾百輪之後，整張地圖就會自動「整理」好——相似顧客集中在同一塊區域。

---

### 怎麼判斷兩位顧客「行為相似」？

SOM 使用**歐式距離**（最直覺的空間距離）來衡量：

```
距離 = √（(R₁−R₂)² + (F₁−F₂)² + (M₁−M₂)²）
```

距離越小 = 兩位顧客的 R、F、M 值越接近 = 行為越相似。

訓練完成後，**落在同一個節點或相鄰節點的顧客，就被視為同一群**。同群顧客的行為特徵相近，可以互相借用彼此的購買資訊來進行推薦。

## Q2：產品推薦區間（PRI）是什麼？怎麼推估購買週期？又怎麼在對的時間推送？

### 核心概念：消費是有規律的

高忠誠度顧客通常有固定的購買節奏，例如：
- 每隔 28 天買一次洗髮精
- 每季購買一次保養品禮盒

PRI 就是**利用這個規律，預測「下次最可能購買的時間窗口」**，在那個窗口內主動推薦，提高命中率。

---

### 購買週期怎麼推估？

**步驟一：整理同一顧客對同一產品的購買日期**

例如顧客 A 購買「洗髮精」的紀錄：
- 1 月 1 日、1 月 30 日、3 月 2 日（約 30 天一次）

**步驟二：計算每次購買的間隔天數**

- 第 1 次間隔：30 天
- 第 2 次間隔：31 天

**步驟三：取平均值作為週期**

平均週期 ≈ 30.5 天

**步驟四：預測下次購買時間**

上次購買日期（3 月 2 日）+ 週期（30.5 天）≈ **4 月 2 日前後**

---

### 怎麼在對的時間推送？

論文設計了一個「推薦區間」（Interval），不是精確在某一天推，而是在預測日期**前後幾天的窗口內**觸發推薦：

```
推薦窗口 = [預測購買日 − 緩衝天數, 預測購買日 + 緩衝天數]
```

當系統偵測到目前日期進入這個窗口，就自動把對應產品推送給該顧客。

**實際意義**：就像超市在你買完牛奶快一週後，在 App 推播「牛奶特價」——時機對了，顧客正好有需求，命中率自然更高。

## Q3：準確率（Precision）是怎麼評估的？

### 最直白的解釋

> **準確率 = 推薦的東西裡，真正被買到的比例**

---

### 用數字舉例

假設系統對顧客 A 推薦了 10 件產品：

```
推薦清單：洗髮精、護髮素、面膜、牙刷、沐浴乳、洗面乳、化妝水、精華液、護手霜、口紅
```

顧客 A 實際在同期購買了以下 3 件（剛好也在推薦清單內）：

```
命中：洗髮精、面膜、化妝水
```

則：

```
Precision = 命中數 / 推薦總數 = 3 / 10 = 30%
```

---

### 準確率高代表什麼？

| Precision | 意義 |
|-----------|------|
| 高（如 70%） | 推薦很「精準」，推 10 個有 7 個被買 |
| 低（如 10%） | 推薦很「亂猜」，推 10 個只有 1 個命中 |

---

### 和召回率（Recall）的差別

這兩個指標看的角度不同：

| 指標 | 問的問題 | 分母 |
|------|----------|------|
| Precision | 我推薦的東西，顧客有買幾個？ | 推薦總數 |
| Recall | 顧客買的東西，我有推薦幾個？ | 實際購買總數 |

**範例延伸**：若顧客 A 那段時間實際買了 5 件產品，但推薦清單只猜中 3 件：

```
Recall = 命中數 / 實際購買總數 = 3 / 5 = 60%
```

**F1 分數**則是把兩者合併為一個數字：

```
F1 = 2 × (Precision × Recall) / (Precision + Recall)
   = 2 × (0.30 × 0.60) / (0.30 + 0.60)
   = 0.40（40%）
```

## 本篇問答小結

| 問題 | 核心答案 |
|------|----------|
| SOM 怎麼建 | 棋盤格節點反覆向真實顧客靠近，最終相似顧客聚集在鄰近格子 |
| 高維顧客 | 顧客有多少個描述指標，就有幾維 |
| 為何映射至二維 | 讓高維資料可視化、可分群，且保留相似關係 |
| 行為相似怎麼判斷 | 歐式距離最小 → 特徵向量最接近 → 落在相鄰節點 |
| PRI 購買週期 | 統計歷史購買間隔取平均，預測下次時間窗口後推送 |
| Precision | 推薦清單中命中的比例（命中數 ÷ 推薦總數） |
